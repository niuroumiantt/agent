# AI 原生 OA 与 agent：首期边界

## 产品定位

统一入口是 `oa.glocalstorage.com`。办公应用在各自流程中持续产生 AI 阅读、整理、
候选提取和建议，agent 负责跨应用理解任务、检索证据、制定计划和协调执行。
它可以在用户授予的范围内成为企业思考与决策中心；思考范围、阅读权限、业务写入
权限、发送身份和最终确认是不同能力，分别由代码与源系统检查。

`agent` 持有任务、来源引用、模型输出、候选建议和产物，不复制一份独立客户主档、
订单账本或合同事实库。用户先在 M5 本机试用，再把成熟能力接入 OA。

## 现有应用边界

| 系统 | 权威数据与职责 |
| --- | --- |
| OA | 组织、权限、审批、办公业务单据与业务任务 |
| Aimail | 原邮件、附件、线程、阅读/草稿结果、邮箱与发件身份 |
| Leadsgen | 客户发现、分配、早期跟进 |
| infra | Spark Ollama、网关、模型路由、设备与部署 |
| agent | 授权任务工作台、工具编排、来源追溯、跨应用计划与派生产物 |

现有 Aimail 实际支持 `local`、`claude` API、`codex_cli`、`claude_code_cli`。
其 CLI 是隔离的文本推理后端，不能直接作为具有文件/业务权限的 agent 执行器。
本试点复用这种分工：模型后端提供结构化推理，工具层独立检查路径、来源和权限。

服务器工作台与 OA/Mail 共用 Authentik 登录，但持有独立 host-only 会话与代理密钥。
当前没有接入 Aimail/OA 的业务 API，不会以自报身份头或直连生产库取得权限。
企业接入需沿用 OA `INVARIANTS.md` I6 与 Aimail 的受信身份、邮箱授权、业务确认合同。

## 首期实现

```
浏览器对话工作台（M5 localhost / agent.glocalstorage.cn）
  → 左侧文件选择 / 对话附件上传
  → 持久对话、上下文与受限操作选择
  → 用户范围内的只读读取
  → 文档解析、出处、哈希、限制
  → 持久任务与不可并发的模型槽
  → Provider：Spark API / 兼容 API / 本机 Codex CLI / 本机 Claude Code CLI
  → 结构化输出与逐字引用核对
  → 本机候选报告、Word、Excel、JSON
```

API 线路是直接 HTTP 请求。已有 `ssh spark` 可转发 Spark loopback Ollama 端口，
不要求模型或 CLI 安装在 M5；M5 的可选 CLI 线路使用该机现有登录。
源码在 `~/code/agent`，私有数据在 `~/.local/share/agent`，更换 M3/M4 不改变代码，
但文件来源、登录和网络必须每机独立配置。当前没有共享多个 Mac 的本地任务数据库。

提交时固定所选文件的扫描指纹，逐文件验证并读取，即使页面重新扫描也不替换任务输入。
全部已提取文字按最多 8000 字符/200 块分段送入模型，保存哈希、读取限制、分段进度和
原文引用。多文件综合归纳基于分段摘要；综合阶段的新引用不当作原文件证据。
仅一项后台任务执行，可请求停止并保留已有结果。模型失败停止后续调用。
凭据文件名与明显密钥标记默认排除，但不构成完整敏感数据识别。
输入原件始终只读。文件变化后要求重新扫描；符号链接、越界与特殊文件拒绝读取。
来源中的文字和文件名不能决定 shell 命令、服务地址或访问范围。

对话控制器依据本轮请求、此前已完成的对话、所选文件名与有限的分析结果选择一次操作：
普通回答、文件分析、原文预览、报告下载、文件刷新、进度查询或停止任务。读取与分析仍
由工具层固定范围并核对来源；控制器不能自行扩大文件选择。明确的停止、进度和下载
指令直接执行，模型工作期间也可使用。连续消息排队执行，不把后续消息加入当前轮上下文。

模型和读取限制在对话中的分析结果可见。当前没有自主 tool-call 循环、全目录持续监控、
自动业务写入、自动发信或桌面控制。消息、任务和报告会持久保存；重启中断的调用标为
中断，需重新提交，暂不宣称恢复到模型执行过程中的精确步骤。

## 演进顺序

1. 在 M5 验证真实材料：文件读取质量、扫描件比例、主模型的 JSON/引用纪律、实际耗时。
2. 接入既有 vision/OCR 线路，分开保留原件、识别文本和核对状态；金额与关键号码回原图。
3. 增加受限工具注册与计划执行：确定性 Excel 运算、文档生成、引用检索，有限步骤与预算。
4. 接入 OA/Aimail 的受权 API：来源深链、候选 PO/合同字段、跨文件比较与持久业务任务。
5. 成熟后在 OA 提供统一工作台与应用内入口，增加用户/部门权限、事件驱动、审阅和审计。

第一阶段以真实材料和任务成功率决定下一项功能，不要求先下载更多模型或部署额外编排平台。

## 已验证与尚未验证

自动测试覆盖目录越界/文件替换、格式读取和限制、结构化输出/来源错误、报告文件与公式样式文本、
任务与对话持久、连续消息上下文、停止与单实例、跨用户文件/对话/报告隔离、浏览器会话
边界，以及模拟 CLI 协议/超时/输出上限。浏览器验证使用合成文件与模拟推理，覆盖上传、
首次文件选择、分析、追问、刷新恢复、内联原文、报告下载与桌面/窄屏布局。

本次开发没有访问用户 M5 Downloads、Spark、真实 CLI 登录或生产 OA。
真实 OCR、Office 排版保真、模型任务成功率、多用户并发与业务授权仍需后续实机验收。

## 2026-10-05 独立服务器入口

`agent.glocalstorage.cn` 的 Caddy 清除浏览器身份头，向 agent 专属 OAuth2 proxy 校验
会话后，以稳定员工 UUID 与独立代理密钥转给应用。OIDC provider 要求 active 且属于
管理员确认的 `GlocalStorage Approved`，不会因为注册即取得工作台权限。
应用不接收任意根目录，所有文件操作限于该 UUID 的上传空间；对话、任务列表、读取、
取消与报告下载再逐项校验归属。进程共用一个模型执行槽，以限制 Spark 并发。CSRF 令牌和
明确来源限制保留；服务端运行仅通过 Caddy 的内部网络暴露，数据卷独立。

服务器模式使用相同的对话入口，以个人上传文件为范围；已有任务可导入对话继续追问。
它不具备本机文件连接器、自主工具循环、业务写入或 OCR。
